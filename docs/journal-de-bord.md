# Journal de bord — UNCHK Office

Suivi chronologique des **problèmes rencontrés** et des **solutions appliquées**, tenu au fil de l'avancement.
Objectif : tracer les décisions et éviter de re-buter sur les mêmes obstacles.

| # | Date | Problème rencontré | Cause | Solution appliquée |
|---|------|--------------------|-------|--------------------|
| 1 | 2026-06-08 | Choix du mode Kafka hésitant (ZooKeeper vs KRaft) | Consigne d'abord « pas KRaft », puis recadrée « sans ZooKeeper » | Adoption de **KRaft** (cluster natif), nœud combiné `broker,controller`, extensible en cluster 3 nœuds |
| 2 | 2026-06-08 | Impossible de compiler le backend en local | Pas de **JDK ni Maven** installés (seulement Node + Docker) | Compilation Java **déléguée à un conteneur Maven** (`maven:3.9-eclipse-temurin-21`), cache `.m2` monté en volume |
| 3 | 2026-06-08 | `ng new` échoue : « Angular CLI requires Node ≥ v24.15.0 » | Angular **20** (latest) exige Node 24.15, or l'environnement est en **24.10** | **Pin d'Angular 19** (pleinement capable, compatible Node 24.10 — simples avertissements `EBADENGINE`) |
| 4 | 2026-06-08 | Générateur `m3-theme` : `Unknown arguments` puis fichier mal rangé | Options en **dash-case** (`--primary-color`…) et `--directory` collé comme **préfixe** du nom de fichier | Bons flags + déplacement manuel du fichier vers `src/styles/_theme-colors.scss` |
| 5 | 2026-06-08 | `.dockerignore` de module inopérants et non conformes | Contexte de build = **racine** (Docker ne lit que le `.dockerignore` racine) ; l'un **nommait** `CLAUDE.md`/PDF (interdit) | Suppression des `.dockerignore` de module, création d'un **`.dockerignore` racine conforme** (exclut le lourd, ne nomme aucun fichier interdit) |
| 6 | 2026-06-08 | `ng build` échoue : `@angular/animations/browser` introuvable | `provideAnimationsAsync()` requiert le paquet **`@angular/animations`**, non installé par le scaffold ni par `ng add @angular/material` | `npm install @angular/animations@^19` |
| 7 | 2026-06-08 | Compilation des services : `EntityName() has protected access` (Document, Budget, Notification, Partner…) | Constructeurs sans-argument JPA déclarés `protected`, mais appelés via `new Entity()` depuis le package `service` (hors package `domain`) | Passage des constructeurs sans-argument concernés en `public` (13 entités/projections) |
| 8 | 2026-06-08 | `insertion-service` test : `no suitable method found for thenReturn(List<Object>)` | Piège varargs Java : `List.of(new Object[]{...})` avec **un seul** tableau est étalé en `List<Object>` au lieu de `List<Object[]>` | Témoin de type explicite `List.<Object[]>of(...)` |
| 9 | 2026-06-08 | Conventions de config **divergentes** entre services (DB_URL vs SPRING_DATASOURCE_URL vs DB_HOST ; issuer JWT `unchk-office` vs URL ; identity sur 8081 vs JWKS attendu sur 8080) | 7 agents indépendants, conventions non harmonisées | Normalisation via un bloc d'env partagé dans `docker-compose` (port interne 8080 partout, identifiants DB unifiés, `JWT_ISSUER=http://identity-service:8080`) — affinage runtime à la mise en route |
| 10 | 2026-06-08 | Image OPA : `0.68.0-rootless` introuvable, puis `latest-rootless` **déprécié** et plante au parsing (`authz.rego:17 : if required`) | OPA a basculé en 1.x ; le tag `*-rootless` est gelé sur une vieille version au parseur incompatible | Pin **`openpolicyagent/opa:1.17.0`** (rootless par défaut en 1.x ; `opa check` valide notre politique) |
| 11 | 2026-06-08 | `docker compose build` échoue : timeouts vers Maven Central | Les 9 Dockerfile retéléchargent **chacun** tout l'arbre de dépendances → saturation/timeout de Maven Central | Cache BuildKit partagé `--mount=type=cache,target=/root/.m2,sharing=locked` sur les `RUN mvn` (téléchargement unique, builds suivants rapides) |
| 12 | 2026-06-08 | Images services : `Could not find artifact unchk-office-parent:pom` | Le Dockerfile installe `common` puis build le service, mais le **POM parent** n'est jamais installé dans le `.m2` (résolu seulement via `relativePath`) | Ajout d'un `mvn -N -f pom.xml install` (parent) avant l'install de `common` dans les 7 Dockerfile |
| 13 | 2026-06-08 | Services crashent : `Schema-validation: column email found [citext], expecting [varchar]` | Flyway crée le schéma avec des types PostgreSQL (`citext`, enum, `inet`) non reconnus par la validation Hibernate (`ddl-auto=validate`) | `SPRING_JPA_HIBERNATE_DDL_AUTO=none` (Flyway = source de vérité du schéma) |
| 14 | 2026-06-08 | Services crashent : `BeanDefinitionOverrideException` sur `kafkaTemplate` | `libs/common` fournit un `KafkaTemplate` JSON qui entre en conflit avec l'auto-config Kafka de Boot | `SPRING_MAIN_ALLOW_BEAN_DEFINITION_OVERRIDING=true` (le template custom prime) |
| 15 | 2026-06-08 | people/communication crashent : `JwtDecoder : expected single bean but found 2` | Boot crée `jwtDecoderByJwkKeySetUri` (via `jwk-set-uri`) **en plus** du `decodeurJwt` de `common` → chaîne de sécurité Boot ambiguë | `@Primary` sur `decodeurJwt` dans `libs/common` |
| 16 | 2026-06-08 | `docker compose up` : `Bind for 0.0.0.0:8085 failed` (kafka-ui) | Port hôte 8085 déjà occupé | Port kafka-ui déplacé en 8090 |
| 17 | 2026-06-08 | Login via gateway → 401 ; login direct → 400 `motDePasse obligatoire` | (a) le gateway exige un JWT sur `/api/identity/auth/login` ; (b) le DTO attend `{email, motDePasse}` (champs FR) | (a) `permitAll` sur `/api/identity/auth/**` dans `SecurityConfig` **et** dans la liste publique du filtre OPA ; (b) payload corrigé |
| 18 | 2026-06-08 | academic/admin/document/insertion → 401 `WWW-Authenticate: Basic` | Ces services n'avaient **pas de chaîne JWT** active et retombaient sur la sécurité Basic par défaut de Boot (config sécurité hétérogène entre agents) | Activation uniforme du resource-server JWT de Boot via env `spring.security.oauth2.resourceserver.jwt.jwk-set-uri` + `issuer-uri` (sans rebuild) |
| 19 | 2026-06-08 | Aucun compte pour se connecter (login impossible) | Identity ne seedait aucun utilisateur | Migration **V3 seed admin** (BCrypt `$2a$`, idempotente) : `admin@unchk.sn` / `Admin123!`, rôle admin |
| 20 | 2026-06-08 | 3 tests unitaires KO (academic/document/communication) + 2 E2E KO | Tests générés sans exécution : ID null du mock `save`, `ObjectMapper` sans module JSR310 ; sélecteur Playwright `getByLabel('Mot de passe')` ambigu (input + bouton « Afficher ») | Mock `save` affecte un ID ; `new ObjectMapper().findAndRegisterModules()` ; sélecteurs E2E par `formControlName`. **Suite verte : backend (9 modules) + E2E 3/3** |
| 21 | 2026-06-08 | **Gateway renvoie des réponses au corps VIDE** (`content-length: 0`) : dashboards vides malgré des données réelles (POST OK mais GET sans corps) | Le filtre OPA lisait `ReactiveSecurityContextHolder` / `exchange.getPrincipal()`, **non propagés dans un GlobalFilter Spring Cloud Gateway** → contexte vide → refus + `setComplete()` qui vide le corps. Détecté car les smoke-tests ne vérifiaient que le code HTTP, pas le corps | Le filtre OPA **décode lui-même le JWT** (déjà validé) via `ReactiveJwtDecoder` pour extraire sujet + rôles ; la corrélation pose son en-tête via `beforeCommit`. Données circulent bout-en-bout (dashboards remplis) |
| 22 | 2026-06-08 | Notifications WebSocket « Hors ligne » : mismatch de protocole (frontend WebSocket brut vs backend STOMP), handshake refusé (le navigateur ne pose pas d'en-tête `Authorization`), et 2 chaînes de sécurité dans le service (resource-server Boot vs `common`) bloquant `/ws` | Réécriture backend en **WebSocket simple** (handler texte) ; JWT passé en `?access_token` et validé au handshake via `JwtDecoder` ; **chaîne de sécurité dédiée `/ws/**` en priorité haute** (permit) ; gateway : `/ws/notifications` public (permit + exclusion OPA) | WS connecté bout-en-bout (session ouverte, push JSON ciblé par utilisateur). NB : une notification ne cible que des utilisateurs propagés par événement — l'admin seedé en SQL n'émet pas d'`identity.users` → 0 destinataire |
| 23 | 2026-06-08 | `docker compose up` ne démarrait pas le frontend (lancé à part via `ng serve`) ; au build, `npm ci` échoue (lock désynchronisé : binaires esbuild multi-plateformes manquants) | Frontend **conteneurisé** (build Node multi-étapes → nginx + routing SPA) ajouté au compose (port 4200, `depends_on` gateway) ; `npm install` tolérant au lieu de `npm ci` dans le Dockerfile | **`docker compose up` démarre toute l'application** (frontend + backend) ; app directement accessible sur http://localhost:4200 |

> Ce journal est mis à jour à chaque nouvel obstacle non trivial. Voir aussi `docs/architecture.md`,
> `docs/security.md` et `docs/database.md` pour les décisions de conception.
